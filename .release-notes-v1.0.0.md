# Kiri v1.0.0 — Phase 1: Windows-Native Recording

Kiri records real product walkthroughs, entirely locally. This release completes Phases 0 and 1: the application foundation and the Windows-native recording pipeline.

## Phase 1 — Windows-native recording and recoverable synchronized sources

- **Display and window capture** through Windows Graphics Capture with H.264 hardware encoding (verified at 1920×1080/60 with zero queue drops)
- **Independent sources**: microphone and system loopback audio (WASAPI, PCM float stereo 48 kHz) and camera (Media Foundation, H.264 1280×720/30)
- **Cursor and click telemetry** with DPI-aware physical/logical coordinate mapping (100%, 125%, 150%)
- **Synchronized sources**: per-source ready offsets committed against a shared QPC recording clock, so sources that start and stop independently stay aligned
- **Pause/resume segmentation** into independently finalized media segments
- **Crash-safe recovery**: forced termination mid-recording still yields every finalized segment
- **Source thumbnails** for the picker, plus standalone capture diagnostics binaries
- New Rust crates: `kiri-capture`, `kiri-audio`, `kiri-camera`, `kiri-input`

## Phase 0 — Foundation and Architecture

- Tauri 2 desktop shell with React, strict TypeScript, and Rust
- Compact Home, source-selector, and recording-controller windows
- System, light, and dark themes with first-paint resolution and cross-window sync
- Versioned portable `.kiri` project format with atomic save, validation, and migration
- SQLite-backed settings and recent-project indexing
- Cancellable background jobs and typed IPC contracts
- Windows Credential Manager boundary with in-memory test implementation

## Quality gate

`pnpm phase1:gate` passed end-to-end: formatting, linting, strict typecheck, frontend unit and golden tests, Rust fmt/Clippy (warnings denied), workspace tests, and the optimized Tauri build. Hardware capture measurements and recovery checks are documented in `docs/VERIFICATION.md`.
